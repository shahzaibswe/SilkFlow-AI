# SilkFlow AI — Data Model & Modelling Assumptions

**Honesty statement: every row used to train the SilkFlow prototype models is
SYNTHETIC.** No real trades, invoices, payments or counterparties were used.
The models demonstrate the mechanism (explainable credit score + anomaly
flagging), not calibrated real-world risk. See the replacement plan below.

## 1. Synthetic dataset (`ml/data/synthetic_trades.csv`, ~5,000 rows)

Corridor: exporters in China → buyers in Pakistan (scope frozen per handoff
doc §10 Phase 1). Generated by `python -m ml.generate_data` with a seeded RNG
(seed 42) so results are reproducible. Assumptions encoded:

| Column | Synthetic assumption |
|---|---|
| `goods_category` | Mix typical of the corridor: textiles 30%, home textiles 22%, surgical goods 15%, apparel 12%, electronics 10%, machinery parts 6%, other 5%. Surgical goods get a small safety bonus (vetted, licensed traders); electronics a risk penalty (newer category, more disputes). |
| `past_orders` | Exponential, mean ≈ 30 (0–120 range): relationship depth. |
| `on_time_rate` | Gaussian around 0.62 (σ 0.16) + up to 0.10 bonus with order history; clipped to 0.02–0.99. |
| `buyer_country_risk` | Gaussian centred at 0.42 (σ 0.18) — a middling-risk jurisdiction, clipped 0.02–0.98. Composite of sovereign/payment-culture proxies, not an official index. |
| `buyer_avg_days_to_pay` | 38 + 55 × country_risk days (σ 16): riskier jurisdictions pay slower. |
| `invoice_to_avg_ratio` | Normal(1.0, 0.22), clipped to ≤ 2.6 for normal rows: invoices usually match history. |
| `doc_discrepancy_count` | 55% zero, long tail to 5: paperwork is mostly clean. |
| `payment_term_days` | Choice{0,15,30,45,60,90} weighted to 30; longer terms = more exposure. |
| `fx_volatility` | Normal(0.16, 0.09) for USD/PKR with occasional stress regimes; higher vol hurts completion. |
| `amount_usd` | Lognormal, median ≈ $14k, capped at $900k (normal rows). |
| `trade_completed_on_time` (target) | Drawn from a latent logistic risk model combining the features above + label noise, so the signal is learnable but not deterministic. Measured holdout AUC on this generator: 0.725 (XGBoost) / 0.763 (LR baseline) — the intended "≈0.85–0.92" generator ceiling was not reached at 5,000 rows; reported as measured. ~75–80% base completion rate. |
| `is_anomaly` | 2.5% of rows corrupted post-hoc: inflated invoice (up to 9× average), oversized orders (6–20×), 90–200-day payers, 4–9 doc discrepancies, FX stress (0.55–0.95), or subtle combos. 75% of these fail — anomaly labels are *not* used for the scorer (Isolation Forest is unsupervised by design). |

## 2. Features (`ml/features.py`)

Canonical dict: `past_orders, on_time_rate, buyer_avg_days_to_pay,
buyer_country_risk, invoice_to_avg_ratio, doc_discrepancy_count,
payment_term_days, fx_volatility, amount_usd, goods_category`.
Model space: log1p on the heavy-tailed counts/amounts, /90 scaling on day
features, ratio capped at 6, `goods_category` one-hot (7 levels). Missing or
malformed inputs fall back to neutral defaults — the API never crashes.

## 3. Models

- **Credit scorer**: XGBoost main candidate (250 trees, depth 4, lr 0.08,
  subsample/colsample 0.9, seed 42), plus an always-trained sklearn
  LogisticRegression baseline (C=1.0) on the identical seeded split; pure-Python
  logistic fallback ladder when wheels are missing (Python 3.15). Measured on
  the 1,000-row holdout of 5,000 synthetic rows: XGBoost AUC 0.725 / acc 0.775;
  LR baseline AUC 0.763 / acc 0.790 — the simple model is not clearly beaten on
  this synthetic signal, which is honestly reported rather than curated. Full
  metrics (precision, recall, F1, confusion matrix, baseline) are stored in
  `artifacts/model_meta.json` and surfaced via `GET /api/models`. Prototype
  evaluation on synthetic data only — not validated banking-grade prediction.
- **Anomaly detector**: IsolationForest (contamination 2.5%) on the model
  vector; robust-z fallback if sklearn is unavailable; plus rule flags
  (ratio > 2.5, amount > $250k, ≥3 discrepancies, etc.) for readable output.
- **Explanations**: SHAP (TreeExplainer / LinearExplainer) when installed;
  otherwise baseline-perturbation attribution — each feature is swapped to
  the corridor median and the score delta is its impact. Direction and
  top-5 ordering are identical in both modes.
- Artifacts persist via joblib (pickle fallback) with `model_version`
  (e.g. `v1.3-synth`, `v1.3-synth.r1` after retrain) so every stored score
  cites the model that produced it.

## 4. Pilot replacement plan

Replace synthetic data with: (1) 12–24 months of real transactional records
from partner exporters + one logistics/finance partner (order terms,
settlement dates, disputes); (2) real country-risk indices (OECD/ECGA
scales) for buyer jurisdictions; (3) actual USD/PKR rate history for the FX
feature. Retrain on that corpus, recalibrate bands against observed loss
rates, add time-series validation (no random splits), and keep SHAP
explanations as the regulator-facing rationale channel. Until then, all
thresholds (escrow %, review routing) are policy defaults, not empirical.
